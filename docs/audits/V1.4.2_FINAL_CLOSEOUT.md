### Root cause: conformance CI failure

The conformance CI job ran `fox-control conformance run --image fox-control:ci`, testing the **management plane** image against the **Fox instance** protocol. Three-layer mismatch:

1. **Port:** SUT mapped container port 8080, but the binary defaults to port 9090
2. **Config:** Container CMD requires `/etc/fox-control/fox-control.toml` which was never mounted
3. **Protocol:** Management plane serves `/healthz` and `/api/*`; instance protocol expects `/health`, `/readyz`, `/version`, `/capabilities`, `/api/v1/auths/signup`

The management plane does not implement the Fox instance HTTP contract. The conformance suite is designed to test Fox instance images (Open WebUI-compatible containers), not the management plane. Fix: gated conformance on `workflow_dispatch`; running it against a proper instance image is a v1.5 scope item.

### Root cause: coverage CI failure

Conformance packages (`conformance/runtime/`, `conformance/plugin/`, `conformance/dataplane/`) are test infrastructure that exercises the binary externally. They contain zero unit-testable logic — their "tests" require a Docker daemon and a running container. Including them in coverage measurement added 6 packages at 0% coverage, dragging the global average from 54.4% to 41.0% (below the 45% gate). Fix: exclude `/conformance/` from the coverage test command.
